# Отправка учебных Google-таблиц на email

## Текущий статус

Функция работает для всех пользователей, которые открывают приложение через Telegram.

Пользовательский сценарий:

1. Пользователь нажимает `Отправить на почту` рядом с Google Таблицей.
2. При первом использовании указывает электронную почту.
3. Email сохраняется по подтверждённому Telegram ID.
4. Письмо приходит от `АРХИТЕКТУРА <materials@mail.arhitektura-app.ru>`.
5. При следующих отправках повторный ввод адреса не требуется.
6. После отправки email можно изменить.

## Что реализовано

- Автоматическое добавление кнопки рядом с действующими ссылками Google Таблиц.
- Поддержка таблиц, заполненных примеров и инструкций.
- Серверная проверка `Telegram.WebApp.initData` через HMAC-SHA-256.
- Разрешены только ссылки вида `https://docs.google.com/spreadsheets/...`.
- Ограничение: не более одного письма в минуту и 20 писем за 24 часа на пользователя.
- Журналирование успешных и неуспешных отправок.
- Сохранение email отдельно от прогресса, ролей и учебных данных.
- Светлая адаптивная форма для iOS, Android и desktop Telegram.

## Почтовый домен

Подтверждённый домен Resend:

```text
mail.arhitektura-app.ru
```

Отправитель:

```text
АРХИТЕКТУРА <materials@mail.arhitektura-app.ru>
```

В DNS должны оставаться действующими записи DKIM, SPF и MX, созданные для Resend. Удалять или изменять их без повторной проверки домена нельзя.

### Таблицы

```text

```

Первая таблица хранит email по Telegram ID. Вторая хранит журнал отправок, статус, идентификатор письма Resend и ошибки.

RLS включён, прямой доступ для `anon` и `authenticated` закрыт.

Историческая миграция:

```text

```

Применённую миграцию не переименовывать и не выполнять повторно без необходимости.

```text
supabase/functions/send-table-email/index.ts
```

Название функции:

```text
send-table-email
```

## Проверка работоспособности

После изменений нужно проверить:

1. Кнопка появляется рядом с реальной Google Таблицей.
2. Кнопка не появляется рядом с обычными сайтами и ссылками-заглушками.
3. Новый пользователь видит форму ввода email.
4. Вводимый текст читается в мобильном Telegram.
5. Письмо приходит в Gmail и Яндекс Почту.
6. Кнопка в письме открывает правильную таблицу.
7. Повторная отправка использует сохранённый email.
8. В `app_table_email_sends` появляется запись со статусом `sent`.

Автоматическая проверка:

```text
.github/workflows/validate-table-email-pilot.yml
tests/table-email-frontend-smoke.mjs
```

Она проверяет синтаксис, распознавание материалов, отсутствие дублирующихся кнопок, блокировку неподходящих доменов, серверные границы безопасности и пользовательские тексты.

## Текущее ограничение

Email сохраняется без отдельного письма-подтверждения. Защита строится на подтверждённой Telegram-сессии, ограничении частоты отправок и запрете произвольных ссылок.

Следующее возможное улучшение — подтверждение email и обработка событий доставки, отказа и жалоб через webhook почтового провайдера.

## Быстрый откат frontend

Для отключения кнопок достаточно удалить из `index.html` две строки:

```html
<link rel="stylesheet" href="table-email.css?v=v142-table-email-mobile-ui-20260727" />
<script src="table-email.js?v=v143-table-email-release-20260727"></script>
```

Удалять учебные материалы, таблицы Supabase или Edge Function для быстрого frontend-отката не требуется.
