# Пилот: отправка учебных Google-таблиц на email

## Что уже реализовано в коде

- Кнопка `Отправить на почту` автоматически появляется рядом с действующими ссылками на Google Таблицы.
- Отдельно поддерживаются кнопки таблиц в дополнительных материалах, даже если URL скрыт внутри JavaScript-функции.
- При первом использовании приложение просит email и сохраняет его по Telegram ID.
- При следующих отправках достаточно одного нажатия.
- После отправки можно изменить email.
- Письмо содержит название материала, кнопку открытия и инструкцию `Файл → Создать копию`.
- Сервер принимает только ссылки вида `https://docs.google.com/spreadsheets/...`.
- Telegram `initData` проверяется сервером через HMAC-SHA-256.
- Ограничение: не чаще одного письма в минуту и не более 20 писем за 24 часа на пользователя.
- Существующие уроки, прогресс, роли, форум и основной `app.js` не изменяются.

## Как включать: два этапа

### Этап A — первый технический тест без DNS

Для первого письма не нужно сразу настраивать собственный домен.

1. Создать аккаунт в Resend на том email, куда будет отправлено первое тестовое письмо.
2. Создать API key и сохранить его в безопасном месте.
3. В Supabase временно указать отправителя:

```text
АРХИТЕКТУРА <onboarding@resend.dev>
```

4. Отправлять тестовое письмо только на email владельца аккаунта Resend.

Тестовый домен `resend.dev` подходит только для проверки интеграции. Для отправки реальным пользователям требуется подтверждённый собственный домен.

### Этап B — включение для пользователей

1. Добавить в Resend собственный почтовый поддомен, например `mail.example.ru`.
2. Добавить предложенные Resend DNS-записи у регистратора домена.
3. Дождаться статуса `Verified`.
4. Изменить секрет `EMAIL_FROM`, например на:

```text
АРХИТЕКТУРА <materials@mail.example.ru>
```

API key нельзя добавлять в GitHub, frontend-код, скриншоты или сообщения.

## Настройка Supabase

### 1. Выполнить миграцию

Проект:

```text
soxtekhspohkddpdidvp
```

Открыть `SQL Editor`, вставить содержимое файла:

```text
supabase/migrations/20260726_table_email_pilot.sql
```

Нажать `Run`.

Миграция создаёт только две изолированные таблицы:

- `app_table_email_profiles` — сохранённый email по Telegram ID;
- `app_table_email_sends` — журнал и лимиты отправок.

Существующие таблицы приложения не изменяются.

### 2. Добавить секреты Edge Functions

Для первого теста:

```text
RESEND_API_KEY=re_...
EMAIL_FROM=АРХИТЕКТУРА <onboarding@resend.dev>
```

После подтверждения собственного домена заменить только `EMAIL_FROM`:

```text
EMAIL_FROM=АРХИТЕКТУРА <materials@mail.example.ru>
```

Существующий секрет:

```text
TELEGRAM_BOT_TOKEN
```

должен остаться без изменений. Значение токена нельзя присылать в чат или добавлять в GitHub.

### 3. Развернуть Edge Function

Функция находится здесь:

```text
supabase/functions/send-table-email/index.ts
```

JWT-проверка Supabase для неё должна быть выключена, потому что функция использует собственную проверку Telegram `initData`:

```toml
[functions.send-table-email]
verify_jwt = false
```

Команды через Supabase CLI:

```bash
supabase link --project-ref soxtekhspohkddpdidvp
supabase db push
supabase functions deploy send-table-email --no-verify-jwt
```

Секреты можно задать отдельно:

```bash
supabase secrets set RESEND_API_KEY="re_..."
supabase secrets set EMAIL_FROM="АРХИТЕКТУРА <onboarding@resend.dev>"
```

## Проверка до слияния в `main`

1. Открыть тестовую публикацию ветки или временно подключить frontend-файлы.
2. Запустить приложение именно из Telegram.
3. Открыть любой урок с Google Таблицей.
4. Нажать `Отправить на почту`.
5. Для первого теста ввести тот же email, на котором зарегистрирован Resend.
6. Проверить получение письма и открытие правильной таблицы на компьютере.
7. Повторить отправку из другого урока — адрес уже не должен запрашиваться.
8. Проверить отправку заполненного примера.
9. Проверить кнопку `Изменить email`.
10. В Supabase открыть `app_table_email_sends` и убедиться, что запись имеет статус `sent`.

После подтверждения собственного домена проверить доставку как минимум в:

- Gmail;
- Яндекс Почту;
- Mail.ru;
- корпоративную почту на собственном домене.

## Известное ограничение пилота

Email сохраняется без отдельного письма-подтверждения. Это осознанное упрощение первой версии. Защита пилота строится на проверке Telegram-пользователя, ограничении частоты отправок и запрете произвольных ссылок вне Google Таблиц.

Перед масштабным публичным запуском рекомендуется добавить подтверждение email и обработку событий доставки/отказа через webhook почтового провайдера.

<script src="table-email.js?v=v140-table-email-pilot-20260726"></script>
